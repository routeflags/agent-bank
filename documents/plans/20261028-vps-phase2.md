## 1. 実行前の確認項目

VPS 上で実行し、結果を記録する（変更は加えない）。

```bash
ss -tln
cat /etc/os-release
free -m
df -h /
cat /etc/ufw/ufw.conf
sudo ufw status verbose   # パスワード入力が必要。取得できなければ未取得として記録する
```

確認観点:

- 待受ポートが `:22` のみであること（80/443/3000 が待受なし）
- スワップが 0 であること（スクリプトの手順 b が新規作成になる）
- UFW の既存ルール内容（取得できた場合のみ。取得できなくても手順は進められるが、結果を記録する）
- 現在の SSH 接続とは別のセッションを 1 つ確保できること（SSH 設定を変更しないが、万一に備える）

## 2. 実行手順

VPS 上でリポジトリを取得し、`feat/agent-bank` ブランチで実行する。

```bash
git pull
sudo bash script/vps_bootstrap.sh
```

スクリプトのステップ一覧:

| 順序 | ステップ | 冪等時の動作 |
|---|---|---|
| 0 | root 権限の確認（`sudo` なしは実行方法を示して終了） | 常に判定 |
| a | 前提確認（OS・カーネル・CPU・ディスク・メモリを表示。`set -euo pipefail`） | 読み取りのみ |
| b | スワップ 2GB 作成（`/swapfile`、`fallocate`、失敗時は `dd`、`chmod 600`、`mkswap`、`swapon`、`/etc/fstab` 追記） | 既存スワップがあれば skip。`/swapfile` が存在し有効でない場合は作り直さず停止 |
| c | `apt-get update && apt-get upgrade -y`（`DEBIAN_FRONTEND=noninteractive`） | 毎回実行 |
| d | 必要パッケージ（`ca-certificates` `curl` `gnupg` `ufw` `git`） | 導入済みは skip |
| e | Docker 公式リポジトリ追加（鍵 `/etc/apt/keyrings/docker.asc`、`signed-by` 指定）→ `docker-ce` / `docker-compose-plugin` 等を導入 | Engine + Compose Plugin 導入済みなら skip |
| f | UFW（`22/tcp` を最初に許可 → `80`/`443` を許可 → `22` 許可確認後のみ `ufw --force enable`） | 既存ルールは削除せず、あれば skip。`22` 未確認なら中止 |
| g | 検証結果を表示（`docker --version`、`docker compose version`、`ufw status`、`free -m`、`ss -tln`） | 読み取りのみ |

変更なしで手順だけ確認する場合:

```bash
sudo DRY_RUN=1 bash script/vps_bootstrap.sh
```

## 3. 実行後の確認コマンドと期待値

```bash
docker --version            # Docker Engine のバージョンが表示される
sudo docker compose version # Compose Plugin のバージョンが表示される
sudo ufw status verbose     # Status: active、22/tcp・80/tcp・443/tcp が ALLOW
free -m                     # Swap: 2047 前後（約 2GB）が表示される
ss -tln                     # :22 が待受。80/443 はアプリ配置後まで待受なしでよい
swapon --show               # /swapfile が表示される
cat /etc/fstab              # /swapfile の行が 1 行だけある（二重追記なし）
```

再実行して全ステップが skip または正常終了することも確認する（冪等の検証）。`swapon --show` と `/etc/fstab` の重複チェックが要点。

## 4. ロールバック

いずれも VPS 上で管理者が実行する。

スワップ解除:

```bash
sudo swapoff /swapfile
sudo rm /swapfile
sudo sed -i '/^\/swapfile[[:space:]]/d' /etc/fstab
```

Docker 停止（コンテナがない初期状態では任意。導入を取り消す場合）:

```bash
sudo systemctl stop docker.socket docker
sudo apt-get purge -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

UFW 無効化（SSH 接続障害時の緊急復旧手段。恒久対策として扱わない）:

```bash
sudo ufw disable
```

> `ufw reset` は使わない（既存ルールを消すため）。ロールバック後もルールは残す。

## 5. 未解決事項

- `sudo` の NOPASSWD 化は行わない。必要性の判断と設定は管理者が個別に行う。本スクリプトは `sudo bash` での実行を前提にしている
- UFW 既存ルールの詳細（`ufw status verbose` / `iptables-save`）は root 権限が必要で未取得。実行時に取得して記録すること
- Ubuntu 26.04 用の Docker 公式リポジトリ suites が未提供の場合、手順 e が失敗する。その場合はエラーを記録し、Docker 側の対応待ちとして Phase 2 を中断する（無理な回避策は取らない）
- SSH の接続元 IP 制限は行わない（接続元 IP が固定か未判定のため）。固定 IP が確定したら別途検討する
- UFW のデフォルトポリシー（`default deny incoming` / `default allow outgoing`）は本スクリプトでは変更しない。既存設定を温存し、指示書 Phase C の適用は既存ルール取得後に判断する
- 外部ネットワークからの到達性検証（指示書 Phase F）は VPS 外からの実測が必要で未検証
- Phase 3 以降（Compose 分離、Caddy、バックアップ等）は未着手
