## 発見項目

### 🔴 高 #1: `ensure_authenticated` が before_action チェーンを停止していない

**対象**: `app/controllers/api/v1/chat_stream_controller.rb` (L117-123)

**問題**:
`ensure_authenticated` は `return if current_user` で早期リターンし、未認証時にストリームにエラーイベントを書き込んでから `response.stream.close` を呼ぶ。しかし `render` / `redirect_to` / `throw :abort` を呼ばないため、Rails の before_action チェーンが停止せず、`show` アクションがそのまま実行される。

未認証時の実行フロー:
1. `ensure_authenticated` → ストリーム書き込み + close
2. `show` アクション実行 → `ChatSession.find` が成功する場合
3. `chat_session.person_id == current_user.id` → `current_user` が nil のため `NoMethodError`
4. `rescue StandardError` で補足 → `sse_write` で closed ストリームに書き込み → `IOError`
5. `IOError` は rescue ブロック内から伝播 → `ensure` → 500 エラーとして記録

**影響**: 未認証アクセス時にサーバーログに 500 エラー (NoMethodError) が記録される。クライアントには正しくエラーイベントが届くが、ログが汚染され、アラートを誤発火させる可能性がある。

**推奨修正**:
```ruby
def ensure_authenticated
  return if current_user

  response.headers['Content-Type'] = 'text/event-stream'
  sse_write(event: "error", data: { error: "Authentication required" }.to_json)
  response.stream.close
  throw :abort  # before_action チェーンを停止
end
```

**問題**:
コメントのスキーマ情報に以下の記載があるが、マイグレーション `20260815000008` で `NOT NULL`制約が除去されている:


### 🟡 中 #2: `seq` カラムが常に 0 のまま — SSE フィルタリングに潜在的な問題

**対象**: `app/channels/persona_chat_channel.rb` (L46-51) / `app/controllers/api/v1/chat_stream_controller.rb` (L72-89)

**問題**:
`persona_chat_channel.rb` の `receive` メソッドでメッセージ作成時に `seq` を指定していない。`seq` カラムは `default: 0` なので、全メッセージの `seq` が 0 になる。

`chat_stream_controller.rb` の SSE フィルタリングは以下のクエリを使用:
```ruby
.where("created_at > ? OR (created_at = ? AND seq > ?)", since, since, last_seq)
```

同一タイムスタンプ（マイクロ秒精度）で複数メッセージが作成された場合、`seq` が同一 (0) ため、2 パス目のフィルタリングでメッセージが欠落する可能性がある。

**影響**: 低確率だが、同時刻に複数メッセージが投稿された場合、SSE 経由でメッセージが欠落する。

**推奨修正**: メッセージ作成時にセッション内の最大 `seq` + 1 を割り当てる:
```ruby
# persona_chat_channel.rb の receive メソッド内
next_seq = chat_session.chat_messages.maximum(:seq).to_i + 1
message = chat_session.chat_messages.create!(
  content: data['content'],
  sender_type: 'Person',
  sender_id: current_user.id,
  role: 'user',
  seq: next_seq
)
```

### 🟢 低 #2: SSE ループの `chat_session.reload` が毎イテレーションで DB 呼び出し

**対象**: `app/controllers/api/v1/chat_stream_controller.rb` (L93)

**問題**:

**影響**: 低。デフォルト間隔で問題になるレベルではないが、本番環境での接続数が多い場合は要注意。
