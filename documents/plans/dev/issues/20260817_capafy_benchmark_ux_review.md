# Issue: Capafy ベンチマーク比較 — マーケットプレイス主要導線と信頼情報の再構築

## 概要

Capafy AI をベンチマークとして、未ログイン状態から「スキルを探す → 比較する → 利用を開始する」までをユーザー目線で確認した。

Lamprey はマーケットプレイスとしての画面構成を備えている一方、検索・カテゴリ・商品カード・利用 CTA が正しい遷移につながっていない。また、購入判断に使われる評価、レビュー、機能、成長実績、出品者認証の一部が固定値または乱数で表示されている。

この状態ではユーザーが主要タスクを完遂できず、表示内容への信頼も形成できないため、Phase 8 の本番リリースを阻害する課題として対応する。

## 優先度

🔴 Critical / リリースブロッカー

## ユーザーストーリー

AI スキルを探しているユーザーとして、目的に合うスキルを検索・比較し、料金や実績を理解したうえで、安全に購入または無料利用を開始したい。

## 現状の問題

### P0-1: 「注目のスキル」カードが 404 になる

`app/views/homepage/index.haml` の注目カードで `listing_path(listing)` に `ListingIndexViewUtils::ListingItem` 構造体全体が渡されている。

生成例:

```text
/ja/listings/%23%3Cstruct%20ListingIndexViewUtils::ListingItem%20id=20,...%3E
```

アクセス結果:

```text
HTTP 404
ActiveRecord::RecordNotFound
Couldn't find Listing with 'id'="#<struct ListingIndexViewUtils::ListingItem id=20>"
```

対象:

- `app/views/homepage/index.haml:129`

期待する状態:

- カードから `/ja/listings/20-tesuto-raiteingu-asisutanto` のような正規URLへ遷移する
- 全カードリンクをリクエストテストで検証する

### P0-2: 検索・カテゴリ・タブ・CTAが主要タスクを実行しない

確認した問題:

- ヒーロー検索入力に `name` がなく、検索語が送信されない
- 「すべてのタイプ」は選択UIとして機能しない
- 人気カテゴリ11件がすべて `category=all` に遷移する
- 「おすすめ」「新着」「高評価」タブに切り替え処理がない
- 商品詳細の「このスキルを利用する」が `href="#"`
- 「お気に入りに追加」が `href="#"`
- `run_online` 商品では画面右下のチャットボタンが別に表示され、主CTAと利用開始導線が分断される

対象:

- `app/views/homepage/index.haml:31-49`
- `app/views/homepage/index.haml:83-117`
- `app/views/homepage/index.haml:122-126`
- `app/views/listings/show.haml:39-50`
- `app/views/listings/show.haml:141-146`
- `app/views/listings/show.haml:211-213`

期待する状態:

- 検索語、カテゴリ、並び順がURLまたは状態へ正しく反映される
- 主CTAからログイン、購入、無料利用、チャット開始のうち商品状態に合う次の操作へ遷移する
- 購入必須エラーになった場合は、購入画面への明確な回復導線を表示する

### P0-3: 評価・レビュー・機能・実績が実データと一致しない

DB確認結果:

```text
testimonials=0
transactions=0
```

一方、画面では以下が表示される:

- トップカード: 全商品一律 `★ 4.8 (0)`
- 商品詳細: `rand(4.0..5.0)` の評価
- 商品詳細: `rand(50..300)` 件の評価
- レビュータブ: `rand(10..200)` 件
- 全商品一律の「検索意図分析」「SEO最適化」「内部リンク提案」「WordPress入力対応」
- 全出品者一律の「認証済み出品者」
- 固定の週間増加値 `+12`、`+38`、`+156`
- 登録スキル数を出品数の3倍として算出

ページを更新するたびにレビュー数と評価が変わり、カードと詳細画面の数字も一致しない。

対象:

- `app/views/homepage/index.haml:57-75`
- `app/views/homepage/index.haml:140-145`
- `app/views/listings/show.haml:46-49`
- `app/views/listings/show.haml:86-99`
- `app/views/listings/show.haml:136-139`
- `app/views/listings/show.haml:151-160`

期待する状態:

- 評価、レビュー、販売数、登録数、成長値はDBまたは集計サービスの実データのみ表示する
- データがない場合は「レビューなし」「販売実績なし」など正直なゼロ状態を表示する
- 機能、対応言語、モデル、バージョン、認証状態は出品ごとの登録値を表示する
- 開発用デモ値が必要な場合は、本番で表示されないfixture/seedへ分離する

### P1-1: 日本語ロケールがログイン前後で維持されない

再現結果:

1. `/ja/login` から `admin2` でログインする
2. ログイン成功後、`/` へリダイレクトされる
3. アカウントに保存されたロケールが優先され、フィンランド語 `fi` で表示される
4. その状態で `/ja/listings/...` を指定しても `/fi/listings/...` へ307リダイレクトされる

また、ロケールなしの `/` と `/login` は英語ロケールだが、独自ナビゲーションとヒーローは日本語で表示され、言語が混在する。

期待する状態:

- 日本市場向けリリースでは初回アクセスの既定ロケールを日本語にする
- ログイン成功後もアクセス元のロケールと戻り先を維持する
- 明示された `/ja/` を保存済みアカウントロケールで上書きしない
- 独自UIの文言をI18nへ移し、ページ単位の言語混在をなくす

### P1-2: 商品情報が購入判断に必要な具体性を満たさない

現状はテスト出品が中心で、`Test Persona`、`Test`、`desc` などの名称・説明が公開一覧に表示される。画像がない出品も多く、すべて同じロボットのプレースホルダーになる。

Capafy では一覧カードだけで、少なくとも以下を比較できる:

- 解決する課題と得られる成果物
- 販売数と評価
- 日次・週次・時間・買い切り等の料金単位
- 無料、無料トライアル
- 制作者の専門性や実績

Lampreyでも以下を商品データとして整備する:

- 誰のどの課題を解決するか
- 入力例と出力例
- 利用モード（オンライン実行、ダウンロード等）
- 課金単位、トークン単価、概算利用料金
- 無料体験の有無と制限
- 外部API、データ送信先、プライバシー条件
- 返金・キャンセル条件
- 出品者の認証根拠

### P1-3: レスポンスが遅く、探索体験を阻害する

確認値:

| 状態 | 応答時間 |
|------|----------|
| コンテナ起動直後のトップ | 約12〜22秒 |
| ウォーム状態のトップ | 約1〜4秒 |
| 最終確認 | 約2.2秒 |

ログ上、トップ表示ではカテゴリ翻訳や関連データ取得が多数発生している。

期待する状態:

- トップページのサーバー応答をローカルのウォーム状態で1秒未満にする
- 一覧取得、カテゴリ翻訳、出品者、画像のクエリ数を計測し、N+1を除去する
- 新しい注目カードと従来のSharetribe一覧を二重に描画する必要性を見直す

## 再現手順

### 注目カードの404

1. Docker環境を起動する
2. `http://localhost:3000/ja/` を開く
3. 「注目のスキル」内の任意の商品を選択する

期待結果:

- 選択した商品詳細が表示される

実際の結果:

- 構造体文字列を含むURLへ遷移し404になる

### 利用CTA

1. 正規URLで任意の商品詳細を開く
2. 「このスキルを利用する」を選択する

期待結果:

- 商品状態に応じてログイン、購入、無料利用、チャット開始へ進む

実際の結果:

- URLが `#` のため処理が開始されない

### 評価表示

1. 商品詳細を開く
2. 表示された評価点とレビュー件数を記録する
3. ページを再読み込みする

期待結果:

- DBに保存された同じ評価値が表示される

実際の結果:

- 評価点とレビュー件数が再読み込みのたびに変化する

## 受け入れ条件

- [ ] 注目カード、一覧カード、検索結果カードの全リンクが正規の商品詳細URLを返す
- [ ] ヒーロー検索からキーワード検索を実行できる
- [ ] 各カテゴリが対応するカテゴリで絞り込まれる
- [ ] おすすめ、新着、高評価の並び順が実データで機能する
- [ ] 商品詳細の主CTAから利用開始フローを完遂できる
- [ ] 未ログイン、未購入、残高不足の各状態に回復可能なCTAがある
- [ ] お気に入り追加・解除が機能し、状態が再表示後も保持される
- [ ] 評価、レビュー、販売数、統計から固定値と乱数を撤去する
- [ ] DBが0件の場合に偽の実績を表示しない
- [ ] 商品固有の機能・モデル・言語・バージョン・認証状態を表示する
- [ ] 日本語で開始したユーザーがログイン後も日本語と戻り先を維持する
- [ ] 公開一覧からテストデータを除外する
- [ ] 料金単位、概算料金、無料体験、データ取扱いを購入前に確認できる
- [ ] トップページのウォーム状態のサーバー応答が1秒未満になる
- [ ] 上記の主要導線をリクエストテストまたはブラウザE2Eテストで保護する

## 推奨実装順序

1. 注目カードURLと主CTAを修正し、主要導線を通す
2. 固定値・乱数・一律認証表示を撤去する
3. 検索、カテゴリ、並び順、タブを実装する
4. ログイン前後のロケールと戻り先を修正する
5. 商品データ項目とゼロ状態を整備する
6. テスト出品を非公開化し、本番品質のサンプルデータを用意する
7. クエリとレンダリングを計測して性能改善する
8. E2Eテストを追加する

## 関連する環境課題

UX改修とは別Issueで扱うが、確認時に以下を検出した:

- `worker` コンテナがRuby 3.4.8で起動し、Gemfile指定の3.4.10と不一致のため終了する
- PayPal IPNホスト未設定警告
- `docker-compose.dev.yml` の `version` 属性廃止警告
- MIME Type初期化APIのdeprecation警告

## 調査上の制約

操作可能なブラウザが実行環境に公開されていなかったため、今回の確認はHTTPレスポンス、HTML、認証リクエスト、DB件数、サーバーログ、実装コードを使用した。視覚的なレスポンシブ表示、キーボード操作、フォーカス遷移、スクリーンリーダー、実ブラウザ上のJavaScript動作は、修正後のE2E確認で追加検証する。
